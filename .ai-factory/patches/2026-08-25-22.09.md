# Enforce hosted cloud contracts at the trust boundary

**Date:** 2026-08-25 22:09 MSK
**Files:** src/cloud/auth.rs, src/cloud/http.rs, src/cloud/mcp.rs, src/cloud/models.rs, src/cloud/snapshot.rs, src/mcp/protocol.rs, tests/fixtures/cloud_test_rsa.pem
**Severity:** high

## Problem

Verification found blocking hosted-cloud gaps: MCP 2026-07-28 responses and error codes were incomplete, OAuth challenges advertised the wrong protected-resource metadata URI and treated insufficient scope as an invalid token, snapshot keys were validated only by prefix, and no authenticated HTTP-to-PostgreSQL-to-MCP round trip ran in CI.

## Root Cause

Validation was implemented as local shape checks instead of reconstructing canonical identities and protocol outcomes. Authentication and authorization shared one error path, while hosted protocol behavior was covered only at helper level. The PostgreSQL test exercised the store directly and therefore could not catch integration drift across HTTP, JWT, validation, persistence, and MCP serialization.

## Solution

- Added the required MCP `resultType`, typed header/version errors, supported-version data, correct unknown method/tool behavior, and required client capabilities metadata.
- Split JWT authentication from scope authorization, corrected the root metadata URI, and added standards-aligned 401/403 challenges.
- Reconstructed every cloud key from record coordinates, verified ownership and references, enforced synchronization path policy, and removed the deleted-project sentinel collision.
- Added an environment-gated authenticated hosted HTTP smoke that pushes Markdown through JWT validation into PostgreSQL and searches it through MCP; the existing cloud PostgreSQL CI job supplies the database.
- Added configurable `[FIX:cloud-protocol]`, `[FIX:cloud-auth]`, and `[FIX:cloud-validation]` diagnostics without logging tokens or document content.

## Prevention

- Treat wire-protocol error mappings and required result discriminators as executable contract tests.
- At ingestion boundaries, validate canonical identities by reconstruction rather than prefixes or loose grammar.
- Keep authentication and authorization failures typed separately so HTTP status and challenges cannot collapse together.
- Require one authenticated cross-layer smoke for hosted features; direct store tests alone are insufficient.
