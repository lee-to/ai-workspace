# Hosted MCP rejected the standard Codex handshake

**Date:** 2026-09-06 17:40
**Files:** src/cloud/mcp.rs, src/cloud/http.rs, docs/cloud.md
**Severity:** high

## Problem

Codex CLI 0.153.2 could not connect to the v1.4.1 hosted endpoint. Its real initialization request reproduced `Header mismatch: Missing or invalid MCP-Protocol-Version header` before this fix, preventing cross-device cloud reads.

## Root Cause

Hosted tests generated only the 2026-07-28 envelope. Ordinary Streamable HTTP clients begin with `initialize` and no negotiated version header, then send an initialized notification. Neither lifecycle operation was implemented. Array-valued `structuredContent` also violated the standard client result shape.

## Solution

Accept standard initialization and negotiate 2025-11-25 or 2025-06-18; acknowledge authenticated notifications with empty HTTP 202 and answer pings. Reuse the existing authenticated, tenant-scoped seven-tool dispatcher. Keep 2026-07-28 header/metadata checks strict whenever modern markers are present. Standard array results retain serialized text without invalid structured content. Add lifecycle, validation, result-shape and authenticated HTTP round-trip regressions; initialization/notification logs contain no client input or tokens.

## Prevention

- Test initialization, notification and a real tool call with a supported client, not only hand-built protocol envelopes.
- Keep protocol negotiation separate from authentication and tool authorization; compatibility paths must enforce the same origin, scope and tenant checks.
- Validate returned payloads against client protocol types, including array results and empty notification responses.
