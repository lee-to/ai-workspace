# Close cloud boundary coverage and reject malformed Origin headers

**Date:** 2026-08-25 23:08 MSK
**Files:** src/cloud/client.rs, src/cloud/http.rs, src/cloud/models.rs, src/cloud/snapshot.rs, tests/cloud_push.rs
**Severity:** high

## Problem

Cloud verification did not exercise aggregate snapshot and request-size limits, client timeouts and no-op retries, HTTP health/auth/origin/content-type boundaries, token-derived tenant isolation, or cloud-log redaction. PostgreSQL-gated tests could also return early when their runtime URL was absent.

## Root Cause

Happy-path tests covered the components but not their external boundaries. Origin parsing also collapsed a malformed header into the same state as a missing optional header, allowing malformed input through.

## Solution

- Reject malformed Origin headers in the shared validator and cover the regression.
- Exercise exact and over-limit request sizes, aggregate snapshots, timeouts, repeated no-op pushes, health/readiness, authentication challenges, content types, document counts, and token-derived cross-tenant reads.
- Assert cloud payload and cloud-module logs exclude tokens, local IDs, paths, sensitive filenames, and document/note content.
- Run the complete suite with explicit administrator and restricted-runtime PostgreSQL test URLs.

## Prevention

- Test missing, malformed, valid, and mismatched trust-boundary headers separately.
- Pair every byte/count limit with exact-boundary and one-over-boundary checks.
- Configure both PostgreSQL test URLs during verification so RLS-gated tests cannot silently skip.
